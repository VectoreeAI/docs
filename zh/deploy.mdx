---

Deploy 会从应用的 GitHub 仓库构建，并给出一个公开访问地址。通过命令行和控制台部署时，一个项目对应一个应用；要部署多个工程，就新建多个项目。之后的更新仍读同一个仓库，地址保持不变。

每一步都可以自己执行，也可以把控制台 **Deploy** 页上的提示词复制给编码助手。

## 开始之前

- 已有 Vectoree Cloud 账号，并且命令行已登录并关联到一个项目（见 [命令行准备](/zh/quickstart)）。
- 应用代码在 GitHub 仓库里，你用来部署的本地目录是这个仓库的克隆。
- 仓库里有 Compose 文件（`compose.yaml`、`compose.yml`、`docker-compose.yaml` 或 `docker-compose.yml`，放在根目录或最多再往下两层）或根目录有 `Dockerfile`。Compose 文件只保留一份。没有 Compose 文件时，使用根目录的 `Dockerfile`。

## 用命令行部署

在应用仓库里运行：

```bash
npx @vectoree/cli login
npx @vectoree/cli link
npx @vectoree/cli github
npx @vectoree/cli deploy
```

| 命令 | 作用 |
|---|---|
| `login` | 在浏览器里登录 Vectoree Cloud。 |
| `link` | 把当前目录关联到一个项目。 |
| `github` | 打开 GitHub 完成授权，然后把这个目录对应的 GitHub 仓库关联到项目。这一步不会部署。 |
| `deploy` | 读取已关联的仓库，构建并发布。完成后会打印公开访问地址。如果还没有授权 GitHub，会先走一遍 `github` 步骤。 |

`deploy` 只在目录干净且已推送时运行：没有未提交的改动，没有还没推到 GitHub 的本地提交，并且 `origin` 指向已关联的仓库。请先提交并推送。

如果 `deploy` 在完成前停住了，再运行一次。它会接着同一个部署任务，而不是另开一个新任务。

### 更新应用

把改动推到 GitHub，然后在同一目录再次运行 `npx @vectoree/cli deploy`。应用会在原地址更新，地址不变。

### 环境变量

```bash
npx @vectoree/cli env list          # 列出变量名
npx @vectoree/cli env set API_KEY   # 保存一个变量；输入值时不可见
```

变量属于已部署的应用，所以要先完成一次部署再设置。它们在下一次部署时生效。部署进行中不能修改。

### 日志

```bash
npx @vectoree/cli logs                   # 列出最近的部署编号
npx @vectoree/cli logs <deploymentId>    # 打印某次部署的构建日志
```

## 在控制台部署

打开控制台侧栏里的 **Deploy**（`/dashboard/runtime-apps`）。页面按三步引导：

<Steps>
  <Step title="关联本地项目">
    复制关联提示词，在本地项目目录里运行，或自己执行 `vectoree link --project <id>`。目录关联成功后，这一步会自动完成。
  </Step>
  <Step title="授权 GitHub">
    授权 GitHub 并关联仓库，或运行 `vectoree github`。权限仅限于你选择的仓库，可在 GitHub 设置里撤销。如果项目还不在 GitHub 上，页面会提供提示词，让助手创建仓库并推送代码。
  </Step>
  <Step title="部署">
    复制部署提示词交给编码助手，或在仓库里运行 `vectoree deploy`。构建和发布完成后，页面会显示地址、状态、部署时间和源仓库。
  </Step>
</Steps>

首次部署之后，在同一页打开 **设置** 可以：

- **停止** 应用。地址会停止访问，直到再次部署。
- **删除** 这次部署。需输入项目名称确认。地址会失效，应用的数据卷会被删除。GitHub 仓库仍保持关联。
- **断开** GitHub。此后项目不能再部署。已经在运行的应用仍可访问。

## 限额

下面是默认数值。平台可以调整，因此实际限额以你所在组织为准。

### 按组织

- **已部署应用：** 每个组织 3 个。如果组织在某个套餐上，以套餐数量为准。达到上限时不会创建新应用，命令行会提示「部署名额已满。」
- **同时进行的构建：** 每个组织 1 个。组织里已有构建在进行时，新的部署不会开始。

### 按项目

- **同一时间只能有一次部署：** 如果该项目已有部署在进行，新的部署不会开始。
- **环境变量：** 每个应用最多 200 个。名称使用字母、数字和下划线，不能以数字开头，最长 256 个字符。每个值最大 8 KB。

### 频率

- **每小时构建：** 每个组织 10 次。
- **每天构建：** 每个组织 10 次。

达到上限时，新的部署不会开始，已有地址仍可访问。

### 体积与时间

- **仓库：** 总计不超过 200 MB，单个文件不超过 10 MB，目录最多 20 层。
- **Compose 文件：** 不超过 256 KB。
- **读取仓库：** 克隆和检查仓库在 120 秒后停止。计时从开始读取算起，不包括排队等待的时间。
- **构建：** 每个服务最多 15 分钟，整次构建最多 30 分钟。
- **构建日志：** 每次构建最多保留 5 MB。

## 应用 ID 规则

每个应用在所属项目里有一个 ID。命令行和控制台的部署流程会从项目名称生成，一般不用自己指定。如果要自己选，必须：

- 只使用小写字母、数字和连字符，并以字母或数字开头和结尾；
- 不超过 63 个字符；
- 不能是 `www`、`api`、`admin`、`dokploy`、`traefik` 或 `mail`；
- 在同一项目内唯一。

## 部署失败时

命令行会给出简要原因和接下来该做什么。常见情况：

| 提示 | 该怎么做 |
|---|---|
| 尚未登录 | 运行 `vectoree login`。 |
| 当前目录尚未关联项目 | 运行 `vectoree link`。 |
| 该项目尚未连接 GitHub / GitHub 授权已过期 | 运行 `vectoree github`，或在 Deploy 页重新连接。 |
| 当前目录是 X，但已绑定的是 Y | 到已绑定仓库的目录里再运行命令。 |
| 构建失败 | 用 `vectoree logs <deploymentId>` 查看构建日志，修好代码后推送并再次部署。 |
| 该项目尚未开通部署 | 这个组织还没有开通部署。 |

如果这次更新失败，原来的地址仍然可以访问。
